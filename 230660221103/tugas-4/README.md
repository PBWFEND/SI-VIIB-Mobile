## 1. Ringkasan Tugas

Dokumen ini berisi hasil analisis kebutuhan perangkat lunak untuk aplikasi bergerak **Kantin Kampus Digital**, meliputi perumusan dua *user persona* (mahasiswa pemesan dan pengelola stan kantin), delapan kebutuhan fungsional berpola aktor–aksi–hasil, tiga kebutuhan nonfungsional terukur, klasifikasi prioritas menggunakan metode MoSCoW, pemetaan kebutuhan ke rencana widget Flutter, serta diagram *user flow* alur pemesanan utama beserta cabang kondisi gagalnya.

## 3. Refleksi

Bagian analisis yang paling sulit ditetapkan adalah **menentukan prioritas fitur menggunakan metode MoSCoW** karena banyak ide fitur terlihat menarik untuk langsung dibuat, namun harus dibatasi maksimal lima fitur pada kategori *Must have* agar realistis dikerjakan hingga tahap MVP[cite: 17, 18]. Selain itu, merumuskan kebutuhan fungsional agar benar-benar terukur dengan pola aktor–aksi–hasil tanpa mencampurkannya dengan solusi teknis implementasi membutuhkan ketelitian ekstra pada setiap pernyataan[cite: 17, 18]. Penyusunan cabang kondisi gagal pada *user flow* juga membantu saya menyadari bahwa alur aplikasi tidak hanya memikirkan kondisi ideal, tetapi harus mengantisipasi stok habis maupun gangguan koneksi di lapangan[cite: 17, 18].
